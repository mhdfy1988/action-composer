# 动作编排（Action Composer）

本地、无模型的二维动作帧校准工具：导入动作 → 首帧整组对齐 → 逐帧微调 → 播放检查 → 导出。

在本项目目录运行。当前只处理本次打开的素材，没有工程操作入口、自动保存或刷新恢复。刷新／关闭会丢失调整，离开前请导出；导出的图片是烘焙结果，不是可恢复编辑历史的存档。

在线入口：[动作编排 · GitHub Pages](https://mhdfy1988.github.io/action-composer/)。网页与本地版使用同一套处理逻辑，图片在浏览器本地处理，不上传；首次打开需要联网加载页面及运行库。线上版同样不自动保存调整。

## 启动

需要 Node.js 24 和 Chrome。首次获取源码：

```powershell
git clone https://github.com/mhdfy1988/action-composer.git
cd action-composer
```

在项目目录运行：

```powershell
npm.cmd ci
npm.cmd start
```

Chrome 打开 [http://127.0.0.1:8914/](http://127.0.0.1:8914/)。服务会构建并监听源码，不替换其他工具的端口。首次构建下载并校验固定 OpenCV 4.13.0 运行库，缓存齐全后无需外网；图片只在本机处理，不上传。

## 使用

导入帧位于右上角、导出素材左侧；底部播放栏提供上一帧／播放暂停／下一帧，适合视图位于上方工具栏的叠加左侧。叠加、对齐使用图标加短标签，锁轴使用锁图标加 X／Y；通用按钮保留图标，悬停显示名称，键盘和屏幕阅读器保留中文名称，选中开关高亮。整组／当前帧位于右侧参数面板顶部，以滑动底块切换。

1. **导入帧**：一次选择同组透明 PNG，确认动作名称、顺序和帧率。单张图默认作为一帧导入，也可在弹窗切换“精灵图”，填写列数、行数、有效帧数，预览后按行优先切帧；宽高须能被行列整除，有效帧数用于排除末尾空格，每组最多 120 帧。精灵图若带本工具的 `animation.json`，同时选择 PNG 和 JSON，自动保留切片、逐帧时长和原点。PNG 序列仍可附带本工具清单或 `uniform-frame-export v6` 的 `frame-sequence.json`。不支持视频、JPG、直接导入 ZIP、带间距的网格或其他引擎的任意图集 JSON；压缩包需先解压。
2. **选择与显示**：左侧复选框控制舞台显示，动作名称选择编辑对象。当前动作正常显示，其他已勾选动作以 40% 不透明度参照；取消当前项会自动切到下一个已勾选动作，全部取消则停止播放并清空选择。播放中也能勾选，沿用共同时间。
3. **整组调整**：右侧滑块选“整组”，显示缩放、水平位置和纵向位置，不显示帧号。点击图片选中，再移动或拖四角等比缩放；右侧数值同步且可输入。只有整组有缩放，当前帧不支持独立缩放或旋转。
4. **当前帧调整**：选“当前帧”，底部切帧，右侧显示帧号与该帧横纵修正；直接拖动角色。画布聚焦且图片选中时，方向键每次 1 舞台像素，Shift + 方向键每次 10 像素。锁轴对两种范围通用；输入框、弹窗和播放不触发方向键移动。一轮拖动一笔记录，Esc 取消。
5. **首帧叠加**：当前动作已校准的首帧以 25% 不透明度参照，只影响观察；首帧自身不重复叠加。看腰部／躯干稳定性，不强求收起的脚贴地。空白拖动、滚轮和适合视图也只改变观察，切帧不自动重新取景。
6. **首帧对齐**：以当前动作为基准，匹配其余全部动作（包含未勾选项），只更新各动作的整组位置和尺度。保留全部逐帧修正，首帧舞台映射也包含已有修正，不重置初始状态。匹配使用 OpenCV 灰度梯度多尺度全身模板，无 AI 模型、无旧算法 fallback；低分、姿态／武器／尾巴干扰仍需人工检查。成功项一次应用，可撤销；失败项保留，取消则整批不发布。
7. **撤销／恢复／重置**：撤销最近一笔；恢复刚撤销的操作，不是重新计算。“重置”按当前选择回溯记录，操作前确认，本身也可撤销／恢复：选整组，仅回溯该动作的整组缩放和位置，保留逐帧修正；选当前帧，仅回溯这一帧横纵修正，保留整组和其他帧。回溯到本次该范围第一次调整前的值，不强行写成零，也不覆盖素材、顺序、时长或锁轴。重置是显式范围操作，不受拖动锁轴限制。
8. **导出素材**：导出名称和留白在导出弹窗设置。当前动作默认带入名称，弹窗中修改仅用于此次输出，不改动作列表或产生编辑历史；选择全部动作时该名称用作素材包名，各动作保留自身名称。留白默认 16px，不影响舞台位置。修改动作本身名称请使用列表中的改名按钮。

正式入口不提供水平腰点补偿与实验性纵向估算。轮廓对齐、纵向估算仅保留在 `experiments/registration/` 供实验／回归，不在后台自动运行或作为对齐失败的隐式兜底。内部保留现有标点数据的校验与几何语义，不新增标点编辑入口。

### 帧与动作管理

- 点击缩略图仅选择当前一帧；没有帧勾选、多选或全选，Ctrl／Shift 点击也只切到一帧，不自动改变右侧整组／当前帧模式。
- 拖动缩略图调整这一帧的顺序，蓝线表示插入位置。时长、横纵修正与标点跟随帧，不因排序丢失。
- 每张帧卡片右下角提供小型复制／删除图标，仅悬停或键盘聚焦时显示，不遮缩略图；无需先选中，按钮操作所在卡片的帧，单纯悬停不切换选择。复制直接在该帧后生成副本，保留原图、时长、帧修正与标点，新帧身份独立；不再提供粘贴或剪贴板。
- 删除仅针对点击按钮所属的帧，需确认；最后一帧转为删除整个动作确认。单组上限仍为120帧。单帧拖动、方向键和数值调整不影响其他帧。
- 左侧动作卡片可拖动排序，蓝线表示插入位置；保留当前选择、显隐和所有动作参数，批量导出沿用列表顺序。悬停或键盘聚焦时显示改名、删除按钮。改名改变动作本身；导出弹窗的名称仍只影响此次输出。帧复制／删除／排序、动作改名／删除／排序均支持撤销／恢复；选择不进入历史。

## 输出

可选当前动作／全部动作，以及 PNG 序列／精灵图；导出范围由弹窗决定，不由显示复选框决定。

- **PNG 序列**：`frames/*.png` 与 `animation.json`，每帧同尺寸、同原点，保留各帧位置和持续时间。
- **精灵图**：`spritesheet.png` 与 `animation.json`，可设 1–64 列（不超过帧数）；清单含单格尺寸、共同原点、整图尺寸、逐帧矩形和时长。
- **全部动作**：测量全部动作所有帧的共同可见范围、加留白，生成相同尺寸和原点。各动作分别放在 `actions/` 子目录，根 `animations.json` 索引；不是把预览中的多个动作合成一个动画。

预览、测量和输出共用 `placement`／`drawFrame`，横纵修正随整组尺度作用，不重复累加。导出不逐帧居中或紧裁，灰底、首帧叠加、选框、基准线不输出。部分空帧保留时长；任一所选动作全透明则拒绝整个输出，取消／失败不下载半成品。

清单是本工具自己的素材协议，不等于 Three.js、Godot、Unity 或 Cocos 的原生格式。尚无引擎适配、多图层合成、武器跟随或插件接入。

## 限制

每组最多 120 帧，当前会话最多 240 帧／24 组；单 PNG 最多 20MB、边长 8192，素材累计 96MB／2400 万解码像素。每帧画布和精灵图最长边 8192、1600 万像素，归档最多 96MB，超出明确拒绝，不裁切或静默降采样。大量重复导入需要导出后刷新释放。

普通撤销保留最近 80 笔元数据快照；范围回溯另保留本次会话的轻量变换记录，不持有图片副本，超过撤销窗口仍能按范围重置。刷新后两类记录均丢失。暂不提供云存储或自动恢复。

### 当前采用的实现方案

- **统一时间与坐标**：每秒60000整数刻度表示逐帧时长，从绝对播放时间定位帧；原图底部中心与项目原点建立映射，观察缩放不修改素材参数。
- **参数化校准，共享绘制**：原图不覆盖，整组变换与逐帧修正分别保存；预览、内容测量和导出共用`placement`／`drawFrame`，避免“预览正确、导出偏移”。
- **正式数据与拖动草稿分离**：`Session`统一管理正式状态和历史，拖动预览不直接改正式数据，确认只提交一笔；重置按整组／当前帧的真实调整记录回溯，而不是清零。
- **有边界的自动对齐**：在Worker中以当前动作首帧匹配其他动作，成功项统一提交；失败保留原样，取消不发布暂存结果，不切回轮廓估算或AI模型。姿态与外观差异仍需人工检查。
- **界面组件与业务规则分层**：模板、局部样式和事件归属组件；应用层协调选择和任务，领域层计算时间／几何，基础设施层适配解码、校验和打包。组件不通过全局ID操纵彼此内部节点。

### GitHub Pages部署

```powershell
npm.cmd run build:pages
npm.cmd run test:pages
```

站点产物仅在`output/pages-site/`，包含首页、应用脚本与样式、匹配Worker、固定OpenCV运行库和许可、构建来源清单；不复制整个仓库、实验页、私人素材或测试输出，也不把构建产物提交到main。首页使用相对资源地址，支持项目子路径。

`test:pages`使用实际压缩产物，在独立临时端口的`/action-composer/`下复用完整浏览器回归，包括后台对齐和真实下载回读；不依赖8914源码服务，也不刷新用户页面。线上同一套验收可显式设置`ACTION_COMPOSER_TEST_URL`后运行`npm.cmd run test:browser`，仅使用合成素材，不上传用户文件。

[Pages工作流](.github/workflows/pages.yml)在main相关源码变化时执行检查、构建和静态子路径验收，再上传白名单产物并部署；纯说明文档修改不触发重新部署，可手动执行工作流。`build-info.json`记录被部署的源码提交及文件摘要，部署状态以[Actions运行结果](https://github.com/mhdfy1988/action-composer/actions/workflows/pages.yml)和实际线上验收为准，不以本地构建成功代替。

`test:browser`默认访问本地8914，须先启动该服务；显式设置`ACTION_COMPOSER_TEST_URL`时则访问指定入口，无需本地8914。测试使用隔离Chrome，不刷新用户页面；通过正式UI、实际下载ZIP／PNG和像素回读验证，不注入内部会话，也不保留隐藏工程控件。可用`ACTION_COMPOSER_REAL_FIXTURE`指定私人样例目录，截图／下载放在忽略的`output/`，不分发私人素材。

`test:components`同样需要8914和Chrome，在隔离页面加载组件公开接口，验证参数面板多实例隔离、局部输入绑定、工具栏意图／禁用、帧节点身份、弹窗取消重开、导出参数及窄屏样式；不启动或注入工作台会话。组件契约测试与正式入口黑盒回归分别证明局部边界和真实装配。

页面入口仅保留文档壳；顶栏、动作库、工具栏、画布区域、参数面板、帧带与各弹窗由`ui/`中的对应组件创建，结构、绑定和局部样式一同归属。`ui/styles.css`仅组织基础／布局与组件样式入口。组件内部查询限定自身根节点，工作台传入数据和操作意图；舞台Canvas是绘制与手势适配共享的显式表面。保留可访问性和测试所需ID，不通过全局ID连接业务。

源码按 `domain`、`application`、`rendering`、`infrastructure`、`ui` 分层。工作台协调选择、显隐与共享任务；导入、导出、动作命令、播放时钟、参数面板和舞台手势分别由独立模块管理。导入执行与弹窗分开，解码、预算和提交可独立验证；`Session` 统一拥有正式数据、独立预览草稿及撤销记录，拖动不直接替换正式数据。范围记录在 `application/scoped-history.js`，协议校验统一在 `infrastructure/validation.js`。模块职责见[代码边界](docs/submission-readiness.md)。内部仍使用 v1 会话数据结构；已清理旧 `.acproj` 读写和基准图迁移实现，`infrastructure/archive.js` 只负责素材输出打包。`check:source` 使用 esbuild 实际依赖图检查正式源码的不可达模块。未引入 Vue、React 或新的运行时依赖。
